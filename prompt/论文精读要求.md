# 任务：在现有工作流基础上，将论文文献模块重构为最简结构

## 零、前提与目标

当前仓库已经有一套论文阅读与复现工作流，顶层结构为：

```text
config/
workflow/
projects/
tools/
tests/
```

本轮目标不是继续加文件，而是做结构收缩：

1. 保持顶层 5 个目录不变。
2. 保持主从模型配置、任务包、运行日志、适配器、CLI、复现模块不变。
3. 把文献模块从“每篇论文 8 个产物 + 多个全局目录”压缩为：
   - 每篇论文 4 个核心文件。
   - 项目级 `INDEX.md` 自动承担分类目录。
   - `reading-list.md` 承担阅读清单。
   - `knowledge-map.md` 承担知识网络。
   - 全局概念仍保留“一个概念一张卡”。
4. 不丢失原有功能：精读、全文翻译、公式拆解、概念综述、领域上下文、代表文献、分类、知识网络、复现线索都要保留。
5. 所有未知信息写 `TODO(user)`，禁止编造论文、引用、公式、实验结果和课题组工作。
6. 不新增复杂依赖。基础依赖仍为 `PyYAML`；PDF 文本提取可选使用 `pypdf`。

先检查当前仓库，如果已经存在上一版文献模块，不要直接删除用户数据。模板可以重构；已有真实论文数据必须保留或提供迁移说明。

## 一、最终最简结构

### 1. 顶层结构保持不变

```text
config/
workflow/
projects/
tools/
tests/
```

不新增任何顶层目录。

### 2. workflow 内部收缩为

```text
workflow/
├── README.md
├── literature.md
├── reproduction.md
├── schemas.yaml
├── prompts/
│   ├── literature-reader.md
│   ├── knowledge-builder.md

    │   ├── analysis.yaml
    │   └── source/.gitkeep
    └── claim/
        └── ...保持现有复现模板...
```

要求：

- 原来的 `workflow/schemas/` 合并为单个 `workflow/schemas.yaml`。
- 原来的 `paper-reader.md`、`context-builder.md` 等提示词，合并进 `literature-reader.md`，通过 `task_type` 区分模式。
- 原来的 `templates/concept/` 合并为单文件 `templates/concept.md`。
- 原来的 `templates/collection/` 删除，阅读清单改为项目模板中的单文件 `reading-list.md`。
- 保持 `templates/claim/` 及其复现功能不变。

### 3. 项目模板收缩为

```text
projects/_template/
├── project.yaml
├── research-profile.yaml
├── INDEX.md
├── 00_inbox/
├── 10_literature/
│   ├── README.md

│   ├── matrix.md
│   └── knowledge-map.md

```

要求：

- 删除 `catalog/` 目录。
- 分类视图改由项目根 `INDEX.md` 自动生成。
- `reading-list.md` 取代 `collections/`。
- `knowledge-map.md` 保留，但由 `wf.py index` 自动生成。
- `matrix.md` 保留，作为跨论文对比矩阵。

### 4. 每篇论文的最终结构

```text
10_literature/papers/<citekey>/
├── meta.yaml
├── source/
├── translation.md
├── reading.md
└── analysis.yaml
```

只有 4 个核心文件：

- `meta.yaml`：身份、分类、状态、索引。
- `translation.md`：全文翻译。
- `reading.md`：全局定位、逐节精读、上下文、局限、复现线索。
- `analysis.yaml`：结构化公式、概念、实验抽取和复现信号。

不再单独创建：

- `overview.md`
- `close-reading.md`
- `formulas.yaml`
- `concepts.yaml`
- `context.md`
- `extraction.yaml`
- `note.md`

这些内容合并进上述 4 个文件，功能不丢失。

## 三、meta.yaml 要求

每篇论文的元数据、分类和状态只写在这里。

```yaml
citekey: TODO
title: TODO
authors: []
year: TODO
venue: TODO
doi: TODO
url: TODO
language: TODO
source_files: []

paper_role: TODO
# survey | classic | group-recent | method | benchmark | application | other

categories: []
topic_tags: []
difficulty: TODO
importance: TODO
reading_priority: TODO

status: unread
# unread | pre-read | reading | deep-read | synthesized

translation_status: none
# none | partial | complete

reading_status: none
# none | partial | complete

analysis_status: none
# none | partial | complete

concept_ids: []
formula_ids: []
next_action: TODO

created_at: TODO
updated_at: TODO
```

分类规则：

- 不按类别建立物理文件夹。
- 一篇论文可以属于多个类别。
- `categories`、`topic_tags`、`paper_role` 是分类来源。
- 分类视图由 `wf.py index` 扫描 `meta.yaml` 自动生成。

## 四、translation.md 要求

全文翻译，不是摘要。

必须：

- 保留原文章节编号、公式编号、图号、表号、引用标记。
- 术语第一次出现时使用：`中文（English）`
- 重要术语链接到 `concepts/<concept-slug>.md`。
- 译者补充说明标为 `[译注]`。
- 长论文按章节分块翻译，逐段追加，不覆盖已完成内容。
- `meta.yaml.translation_status` 记录进度。
- 原文是中文时，改为逐段白话转写和术语解释，不做机械翻译。

禁止：

- 用概括代替翻译。
- 漏段。
- 编造原文中不存在的内容。

## 五、reading.md 要求

这是详细精读的主文件，必须包含以下固定章节：

```markdown
# 论文精读：<citekey>

## 1. 全局定位
## 2. 论文地图与逻辑链
## 3. 逐节精读
## 4. 方法与公式
## 5. 实验设计与结果
## 6. 前因后果与代表文献
## 7. 局限性与边界条件
## 8. 与当前研究方向的关系
## 9. 复现线索
## 10. 待验证问题
## 11. 证据与来源索引
```

各章节要求：

### 1. 全局定位

- 研究对象是什么？
- 核心问题是什么？
- 为什么重要？
- 论文处于领域什么位置？
- 改变了什么旧认知？
- 依赖哪些前置概念？

### 2. 论文地图与逻辑链

- 每一节在做什么。
- 各节之间如何衔接。
- 核心论证链是什么。

### 3. 逐节精读

- 每节的目的、假设、方法、证据、结论。
- 作者原文、作者声称、实验证据、读者推断必须区分。
- 重要结论附来源引用。

### 4. 方法与公式

- 解释方法流程。
- 公式详细拆解写入 `analysis.yaml.formulas`。
- 正文中引用 formula id。
- 说明假设、直觉、特例、失效条件。

### 5. 实验设计与结果

- 数据集、baseline、指标、消融、失败案例。
- 结果是否支持作者结论。
- 实验设置是否公平。
- 计算资源和可复现条件。

### 6. 前因后果与代表文献

- 前置工作。
- 同期竞争方法。
- 后续影响。
- 代表综述。
- 经典论文。
- 课题组近期工作。
- 未解决问题。
- 推荐阅读顺序。

如果代表文献不在本地，写 `TODO(user)`，不要编造。

### 7. 局限性与边界条件

- 作者承认的局限。
- 未承认但存在的局限。
- 假设失效后会怎样。
- 哪些结论不能外推。

### 8. 与当前研究方向的关系

- 可以直接借用什么。
- 需要改造什么。
- 与 `research-profile.yaml` 的匹配程度。

### 9. 复现线索

- 代码链接。
- 数据链接。
- 关键实验。
- 可线上复现部分。
- 可能需要线下实验部分。
- 建议交给复现模块的 claim 候选。

### 10. 待验证问题

- 翻译疑点。
- 公式疑问。
- 概念空缺。
- 数据或实验疑问。

### 11. 证据与来源索引

- 页码、段落、图表编号、公式编号。
- 对应到具体文件和位置。

要求：

- 论文没有公式时，`formulas` 可以为空列表，但不能缺字段。
- `reading.md` 与 `analysis.yaml` 不能重复维护同一份结构化状态。
- `analysis.yaml` 负责机器可校验数据。
- `reading.md` 负责解释、推理和上下文。

# not-started | learning | understood | needs-review

正文至少包含：

## 十、工作流与角色

更新 `workflow/literature.md`，定义：

```text
0. 入库与分类
1. 全局预读
2. 分段翻译与精读
3. 公式与概念深挖
4. 代表文献与领域上下文
5. 跨论文知识网络
6. 验证与综合
```

角色压缩为：

- `literature-reader`
  - 全局预读
  - 分段翻译
  - 逐节精读
  - 公式拆解
  - 概念提取
  - 上下文整理
- `knowledge-builder`
  - 全局概念卡
  - 前置/继承/对比关系
  - 高频概念
  - 知识网络
- `verifier`
  - 翻译核对
  - 公式核对
  - 概念引用核对
  - 反幻觉检查

不再单独设置：

- `paper-reader`
- `context-builder`

这些能力通过 `literature-reader.md` 中的 `task_type` 区分：

```yaml
task_type: literature-first-pass
task_type: literature-translate
task_type: literature-close-read
task_type: literature-formula
task_type: literature-context
```

配置保持简单：

```yaml
subagents:
  literature-reader:
    enabled: true
    adapter: manual

  knowledge-builder:
    enabled: false
    adapter: manual

  verifier:
    enabled: true
    adapter: manual

routing:
  literature-first-pass: literature-reader
  literature-translate: literature-reader
  literature-close-read: literature-reader
  literature-formula: literature-reader
  literature-context: literature-reader
  literature-knowledge: knowledge-builder
  verification: verifier

fallback:
  knowledge-builder: literature-reader
```

要求：

- `knowledge-builder` 未配置时自动回退到 `literature-reader`。
- 使用者仍然只改 `config/models.local.yaml`。
- 不因为重构增加配置复杂度。

## 十一、CLI 调整

保留命令：

```bash
python tools/wf.py bootstrap
python tools/wf.py doctor [--offline]
python tools/wf.py init <slug> --title "..."
python tools/wf.py new paper <project> <citekey>
python tools/wf.py new concept <project> <concept-slug>
python tools/wf.py index <project>
python tools/wf.py validate <project>
python tools/wf.py run <project> <task.yaml>
python tools/wf.py demo
```

可选命令：

```bash
python tools/wf.py ingest <project> <citekey> <pdf>
```

删除命令：

```bash
python tools/wf.py new collection <project> <topic-slug>
```

原因：`reading-list.md` 已经是项目模板中的固定文件，直接维护即可。

`new paper` 必须生成最简结构：

```text
meta.yaml
translation.md
reading.md
analysis.yaml
source/
```

`index` 必须生成：

- 项目根 `INDEX.md`
- `10_literature/knowledge-map.md`
- 必要时生成 `matrix.md` 基础表格

`validate` 必须检查：

- 4 个核心文件是否存在
- YAML 是否合法
- `meta.yaml` 关键字段是否合法
- 状态字段是否合法
- 公式 ID 是否重复
- 概念引用是否存在
- `source_refs` 是否可追溯
- `reading.md` 状态为 complete 时是否包含必要章节
- `translation.md` 状态为 complete 时是否仍然包含大段 `TODO`
- `reading-list.md` 中的 citekey 是否存在
- 旧结构文件只给迁移警告，不静默删除

## 十二、兼容与迁移

如果发现旧文件：

- `overview.md`、`close-reading.md`、`context.md`、`note.md`
  - 合并进 `reading.md` 对应章节。
- `formulas.yaml`、`extraction.yaml`
  - 合并进 `analysis.yaml`。
- `concepts.yaml`
  - 概念引用合并进 `analysis.yaml.concepts`。
  - 全局概念内容合并进 `concepts/<slug>.md`。
- `collections/`
  - 合并进 `reading-list.md`。
- `catalog/`
  - 删除目录，重新运行 `wf.py index` 生成项目根 `INDEX.md`。
- `knowledge-map.md`
  - 保留，重新生成。
- `matrix.md`
  - 保留，重新生成基础表格。

迁移原则：

1. 不删除用户原始论文、翻译、精读内容。
2. 能自动合并就自动合并。
3. 不能自动合并时，保留旧文件并输出迁移提示。
4. 没有实际论文数据时，直接替换模板为空的最简结构。

更新复现模块引用：

- 原来的 `close-reading.md` 改为 `reading.md`。
- 原来的 `extraction.yaml` 改为 `analysis.yaml.extraction`。
- 原来的 `formulas.yaml` 改为 `analysis.yaml.formulas`。
