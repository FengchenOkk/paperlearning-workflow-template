## 一、配置改为 Profile 模式

修改 `config/models.example.yaml`。

### 1. 主模型

主模型认证不放进仓库，只引用 Codex 的 profile：

```yaml
orchestrator:
  adapter: codex
  profile: main
  model: inherit
  auth: external
  api_key_env: null
```

要求：

- Codex+GPT 由使用者本机安装 Codex CLI 后自行登录或配置。
- 仓库只负责说明如何使用，不保存任何主模型密钥。
- 如果对方没有 Codex，也可以改用其他能读取 `AGENTS.md` 的 agent，或使用 manual 模式。
- `doctor` 只检查 Codex 命令是否存在，不打印任何认证信息。

### 2. 子模型 Profiles

```yaml
settings:
  default_subagent_profile: manual

subagent_profiles:
  manual:
    adapter: manual
    description: 无 Key 模式，生成 prompt 后由使用者人工执行
    timeout_seconds: 600
    max_concurrency: 1
    privacy: local

  deepseek:
    adapter: openai_compatible
    provider: deepseek
    base_url: https://api.deepseek.com
    model: deepseek-chat
    api_key_env: DEEPSEEK_API_KEY
    capabilities: [text, reasoning]
    timeout_seconds: 900
    max_concurrency: 1
    cost_tier: low
    privacy: external
    fallback: manual

  # 其他 OpenAI-compatible 服务示例
  # my-provider:
  #   adapter: openai_compatible
  #   provider: TODO
  #   base_url: TODO
  #   model: TODO
  #   api_key_env: MY_PROVIDER_API_KEY
  #   fallback: manual
```

要求：

- `manual` 默认可用，不需要任何 Key。
- `deepseek` 是预设示例，使用者填自己的 Key 后即可启用。
- 使用者只改 `settings.default_subagent_profile`，或单个角色的 `profile`。
- 不在每个角色里重复填写 `base_url`、`model`、`api_key_env`。
- 某个 profile 不可用时，自动回退 `manual`。
- DeepSeek 的 model 名、base_url 如与官方文档不一致，以官方当前文档为准，并在 README 中标注可修改。

### 3. 子模型角色

保持现有角色不变，只让每个角色引用 profile：


## 二、.env.example 与 .gitignore

### 1. `.env.example`

只允许变量名和占位值：

```dotenv
# DeepSeek 子模型
DEEPSEEK_API_KEY=

# 如果主模型使用 API 模式，可在本机自行设置，不建议写入仓库
# OPENAI_API_KEY=
```

要求：

- 不写真实 Key。
- `bootstrap` 可以从 `.env.example` 生成 `.env`。
- `doctor` 只报告环境变量是否设置，不打印值。
- 系统环境变量优先，`.env` 只作为本地补充。
- API Key 不允许写入 `models.local.yaml`。

### 2. `.gitignore`

必须忽略：

```text
.env
config/models.local.yaml
**/.runs/
__pycache__/
*.pyc
```

同时忽略：

- PDF 和原始论文大文件。
- 未脱敏实验数据。
- 私密数据。
- 模型生成的临时大文件。

如果曾经误提交真实 Key：

- README 中必须说明立即去服务商后台撤销。
- 重新生成 Key。
- 不要只删除文件而不撤销 Key。

`python tools/wf.py doctor [--offline]` 必须报告：


要求：

- 绝不打印 Key 的内容。

  - 检查结果不打印完整 Key。

## 五、README 增加“别人如何使用我的模板”

README 中必须写清三种模式。

### 模式 A：有 Codex + DeepSeek API

1. 安装 Python 3.11+。
2. 执行：
   ```bash
   pip install -r requirements.txt
   python tools/wf.py bootstrap
   ```
3. 按 Codex 官方当前方式安装并认证 Codex CLI。
4. 编辑 `config/models.local.yaml`：
   ```yaml
   settings:
     default_subagent_profile: deepseek
   ```
5. 在本地 `.env` 中填写：
   ```dotenv
   DEEPSEEK_API_KEY=使用者自己的Key
   ```
6. 执行：
   ```bash
   python tools/wf.py doctor
   python tools/wf.py demo
   ```

### 模式 B：没有任何 API Key

1. 安装 Python。
2. 执行：
   ```bash
   pip install -r requirements.txt
   python tools/wf.py bootstrap
   python tools/wf.py doctor
   ```
3. 保持 `default_subagent_profile: manual`。
4. 执行：
   ```bash
   python tools/wf.py run <project> <task.yaml>
   ```
5. 工作流会生成标准 prompt 文件，使用者复制到自己常用的模型界面执行，再把结果写回 `response.md`。
6. 可以先用 `python tools/wf.py demo` 验证整套流程，它使用 mock，不需要 Key。

### 模式 C：有其他 OpenAI-compatible 模型

1. 在 `subagent_profiles` 中新增 profile：
   ```yaml
   my-model:
     adapter: openai_compatible
     provider: TODO
     base_url: TODO
     model: TODO
     api_key_env: MY_MODEL_API_KEY
     fallback: manual
   ```
2. 在本地 `.env` 中填写：
   ```dotenv
   MY_MODEL_API_KEY=使用者自己的Key
   ```
3. 把角色 `profile` 改为 `my-model`。
4. 执行：
   ```bash
   python tools/wf.py doctor
   ```

README 必须明确说明：

- 主模型认证由每个人自己在本机完成。
- 子模型 Key 由每个人自己配置。
- 模板上传前必须确认没有 `.env`、`config/models.local.yaml`、`.runs/`、真实 PDF 和私密数据。
- 如果误传 Key，必须立即撤销并重新生成。
